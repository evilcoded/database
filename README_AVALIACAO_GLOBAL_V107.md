# V107 integrated reference valuation for global holdings

Unifies the existing accounts/live projection with the existing universal cockpit valuation. The accounts API previously looked up the asset suffix in the legacy snapshot and used `price_eur` only for EUR holdings. The new implementation uses the existing exact instrument/account/currency valuation for every currency, with explicit quote bindings and reviewed reference compatibility where identities differ. No symbol join, silent FX, fallback to principal or zero unknown cost is introduced.

The existing reference-reconciliation module can now derive a separate read-only reference chain for verified post-cutover positions whose account status is EXPLICIT_TRANSACTION_ACCOUNT. It requires the canonical read-model contract, a verified ledger head, unique position scope, current registered account currency, an existing explicit reviewed research identity link, and a unique active provider/currency binding. Provenance retains the ledger head and a digest of the scoped position. No canonical binding record is manufactured or persisted. Existing confirmed legacy position bindings and authority semantics remain unchanged.

The shared cockpit rejects future/naive quote timestamps, filters ambiguous or mismatching explicit provider bindings, and exposes quote time, age, provider and non-execution-reference status. New position principal/cost remains distinct from reference market value. Live positions expose reference P/L and P/L percentage, source/time, explicit asset-class metadata when known, and valued/unvalued coverage. Unknown cost is not normalized to zero. Account-reference fallback is explicit and conflicting account IDs are not merged.

The existing account popup shows the same reference value, unrealized gain/loss and source/time without a new financial UI or store. The dashboard's existing allocation, position and P/L consumers continue to use the same cockpit facts. Existing operational P/L snapshot precedence remains unchanged. Filters and the existing purchase review/confirmation flow remain intact.

Prices are the existing daily research captures, with age and source identified; they are NOT live execution quotes. This package adds no network provider, no intraday acquisition loop and no financial or training writer. No past chart points are reconstructed using today's holdings. Missing reference evidence leaves valuation unavailable. Other unvalued holdings still make overall currency coverage partial.

Validation: 88 existing focused tests (cockpit, position reconciliation, monitor, panels, intraday) plus 10 new tests for post-cutover reference chains, provider/currency isolation, verified-head requirements, quote time, ambiguity, new-position P/L and the shared live API. UI metadata/escaping, prior exact-ID handoff, datetime/zero-fee validation and filter checks also pass. Installer five-file preflight, repeat and divergence checks pass. No live source request, real ledger write or historical/model alteration is performed by installation/tests. Actual user's current quote matching and source availability remain to be verified after deployment.

Older legacy-only live-projection fixtures that assume EUR snapshot enrichment describe the replaced price-source contract; the replacement is covered with exact-scoped source fixtures. This change deliberately removes that ticker-based EUR enrichment from the live accounts projection while retaining the existing global runtime ownership/cash authority.
